# FTPServer for ESP8266, ESP32 and ESP32-C3

[English Version](README_EN.md)

Легковесная, надежная и быстрая библиотека чистого FTP-сервера для микроконтроллеров **ESP8266**, **ESP32** (Xtensa) и **ESP32-C3** (RISC-V) с поддержкой **LittleFS**, **SPIFFS**, **SD** и **FFat**.

Библиотека разработана как бескомпромиссная замена устаревшим и нестабильным реализациям, оптимизирована для работы в условиях ограниченной оперативной памяти и обеспечивает максимальную скорость и бережное отношение к ресурсу Flash-памяти.

---

## Особенности и преимущества

1. **Только сервер (Server-Only)**:
   - Полное избавление от лишнего кода FTP-клиента и абстрактного базового класса `FTPCommon`.
   - Существенная экономия Flash-памяти (более 7 КБ на ESP8266) и нулевой оверхед.
2. **Нулевая фрагментация кучи (Zero Heap Fragmentation)**:
   - Приём команд выполняется в фиксированный буфер `char` без побайтовой реаллокации строк (`String += c`).
   - Ответы протокола форматируются на стеке через `vsnprintf` без динамических вызовов `malloc` / `free` на каждый чих.
   - Буфер передачи данных (1460 байт = TCP MSS) выделяется динамически **только на время активного трансфера** и сразу освобождается. В режиме ожидания сервер не держит буфер передачи в RAM.
3. **Безопасность для RISC-V (ESP32-C3 / C6)**:
   - Исключены невыровненные 32-битные касты указателей (`*(uint32_t*)`), приводившие к аппаратным сбоям (`Load Alignment Fault`) на архитектуре RISC-V.
   - Парсинг команд выполняется через безопасный `strcasecmp`.
4. **Корректная обработка файлов с дефисами (`-`)**:
   - Устранён критический баг старых библиотек (`path.lastIndexOf("-")`), повреждавший имена файлов вида `firmware-v1.bin`, `wifi-config.json` и каталогов с дефисами.
   - Флаги команд (`LIST -la`, `LIST -a`) корректно фильтруются без искажения целевых путей.
5. **Буферизованная запись во Flash (LittleFS)**:
   - Приём файлов (`STOR`) буферизуется блоками по 1460 байт. Это предотвращает запись крошечными порциями по 10–50 байт, снижает износ Flash-памяти (write amplification) и в разы повышает скорость загрузки.
6. **Автоматическое создание подкаталогов**:
   - При заливке файлов по пути с несуществующими папками (например `/data/logs/test.txt`), сервер автоматически создаёт все промежуточные каталоги.
7. **Совместимость с Arduino Cores 3.x и 2.x**:
   - Корректное использование `accept()` для ESP32/ESP8266 Core 3.x и фоллбек на `available()` для старых ядер.
   - Полное отсутствие внешних зависимостей от устаревшего `PolledTimeout`.
8. **Инкапсулированные сокеты**:
   - `WiFiServer` инкапсулирован внутри объекта класса, а не объявлен глобально. Порты настраиваются через конструктор (по умолчанию 21 и 50009).

## Архитектура библиотеки

Библиотека построена на базе однопоточной неблокирующей модели конечного автомата (FSM):

```
+-----------------------------------------------------------+
|                        handleFTP()                        |
|                                                           |
| 1. _ctrlServer.accept()    -> Приём входящего подключения |
| 2. Inactivity Timeout      -> Проверка таймаута (millis)  |
| 3. State: RETR / STOR      -> Потоковый трансфер (1460 B) |
| 4. Command Parser          -> Чтение строки и выполнение  |
+-----------------------------------------------------------+
```

* **Разделение каналов управления и данных**: канал команд (`Control`, порт 21) управляет состоянием сессии и аутентификацией, а канал данных (`Data`, пассивный порт 50009 или активный порт клиента) открывается исключительно на время листинга каталогов или передачи файлов.
* **Полиморфизм файловых систем**: класс принимает ссылку на базовый интерфейс `fs::FS &`, благодаря чему сервер «из коробки» совместим с LittleFS, SPIFFS, SD, SD_MMC и FFat.
* **Неблокирующая передача**: вызовы `transferFileToNetwork()` и `transferNetworkToFile()` передают данные квантами фиксированного размера (1460 байт) за один проход `handleFTP()`, не блокируя основной цикл программы и не приводя к срабатыванию аппаратного сторожевого таймера (WDT).

## Установка

### PlatformIO
Добавьте репозиторий в файл `platformio.ini` вашего проекта в секцию `lib_deps`:
```ini
[env:my_board]
lib_deps =
    https://github.com/SerhiiLe/FTPServer.git
```
Или просто скопируйте папку `FTPServer` в локальную директорию `lib/` вашего проекта.

### Arduino IDE
1. Скачайте репозиторий в виде архива: [FTPServer.zip](https://github.com/SerhiiLe/FTPServer/archive/refs/heads/master.zip).
2. В Arduino IDE перейдите в меню: **Скетч** -> **Подключить библиотеку** -> **Добавить .ZIP библиотеку...** и выберите скачанный файл.
3. Либо клонируйте репозиторий напрямую в каталог библиотек:
   ```bash
   cd ~/Arduino/libraries  # или Документы/Arduino/libraries в Windows
   git clone https://github.com/SerhiiLe/FTPServer.git
   ```

### Зависимости
Библиотека полностью самодостаточна и не требует внешних сторонних библиотек. Используются только стандартные компоненты ядра Arduino для ESP8266 и ESP32 (`WiFi`, `FS`, `LittleFS`).

## Описание методов API

### Конструктор
```cpp
FTPServer(fs::FS &fs, uint16_t ctrlPort = 21, uint16_t dataPort = 50009);
```
* `fs`: ссылка на экземпляр файловой системы (например `LittleFS`).
* `ctrlPort`: порт управляющего соединения FTP (по умолчанию `21`).
* `dataPort`: порт пассивного соединения данных (по умолчанию `50009`).

### `begin`
```cpp
void begin(const String &user = "", const String &pass = "");
```
Запускает прослушивание портов. Если логин и пароль опущены или переданы пустые строки `""`, разрешён анонимный вход.

### `stop`
```cpp
void stop();
```
Останавливает сервер, корректно закрывает активные сокеты клиентов и освобождает выделенные буферы.

### `handleFTP`
```cpp
void handleFTP();
```
Главный рабочий метод. Обрабатывает входящие подключения, разбор команд и передачу файлов. Должен регулярно вызываться в функции `loop()` Arduino.

### `isConnected`
```cpp
bool isConnected();
```
Возвращает `true`, если в данный момент к серверу подключен активный клиент.

### `setTimeout`
```cpp
void setTimeout(uint32_t timeoutMs);
```
Задает время таймаута неактивности клиента в миллисекундах (по умолчанию `300000` мс = 5 минут). По истечении этого времени клиент автоматически отключается.

## Управление активностью сервера

Сервер можно легко включать и выключать по условию или флагу без перезагрузки контроллера (паттерн из проекта `Clock_Mini`):

```cpp
#include <LittleFS.h>
#include <FTPServer.h>

FTPServer ftpSrv(LittleFS);
bool ftp_isStarted = false;
bool ftp_isAllow = false; // Флаг включения/выключения из настроек или веб-интерфейса

void ftp_process() {
    if (ftp_isStarted) {
        if (ftp_isAllow) {
            ftpSrv.handleFTP();
        } else {
            ftpSrv.stop();
            ftp_isStarted = false;
        }
    } else {
        if (ftp_isAllow) {
            ftpSrv.begin("admin", "password123");
            ftp_isStarted = true;
        }
    }
}
```

## Поддерживаемые команды FTP

| Команда | Описание |
| :--- | :--- |
| `USER`, `PASS` | Аутентификация пользователя (или анонимный вход) |
| `QUIT` | Завершение сессии и отключение |
| `PWD`, `XPWD` | Вывод текущего рабочего каталога |
| `CWD`, `XCWD` | Смена текущего каталога (поддерживает `.`, `..` и абсолютные/относительные пути) |
| `CDUP`, `XCUP` | Переход в родительский каталог |
| `PASV` | Переход в пассивный режим передачи (рекомендуемый для большинства клиентов) |
| `PORT` | Переход в активный режим передачи данных |
| `TYPE` | Установка типа данных (`A` — ASCII, `I` / `L 8` — Binary) |
| `STRU` | Структура файла (`F` — File) |
| `MODE` | Режим передачи (`S` — Stream) |
| `LIST` | Листинг файлов в стандартном формате Unix (поддерживает флаги `-la`, `-a`, `-l`) |
| `MLSD` | Машиночитаемый листинг каталога по стандарту RFC 3659 |
| `NLST` | Простой список имён файлов |
| `RETR` | Скачивание файла с устройства |
| `STOR` | Загрузка файла на устройство (с автосозданием промежуточных папок) |
| `DELE` | Удаление файла |
| `MKD`, `XMKD` | Создание директории |
| `RMD`, `XRMD` | Удаление директории |
| `RNFR`, `RNTO` | Переименование и перемещение файлов |
| `SIZE` | Получение точного размера файла |
| `MDTM` | Получение времени последней модификации файла |
| `FEAT` | Список поддерживаемых расширений протокола |
| `SYST` | Тип операционной системы (`UNIX Type: L8`) |
| `NOOP` | Проверка связи (No operation) |
| `ABOR` | Прерывание текущей передачи данных |

## Базовый пример

Полный готовый скетч находится в папке [`examples/FTPServerBasic/FTPServerBasic.ino`](examples/FTPServerBasic/FTPServerBasic.ino).

```cpp
#include <Arduino.h>
#include <LittleFS.h>
#include <FTPServer.h>

#if defined(ESP8266) || defined(ARDUINO_ARCH_ESP8266)
  #include <ESP8266WiFi.h>
#elif defined(ESP32) || defined(ARDUINO_ARCH_ESP32)
  #include <WiFi.h>
#endif

FTPServer ftpServer(LittleFS);

void setup() {
    Serial.begin(115200);
    LittleFS.begin();

    WiFi.begin("WiFi_SSID", "WiFi_PASSWORD");
    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
    }

    // Запуск сервера с логином и паролем
    ftpServer.begin("esp", "esp");
}

void loop() {
    ftpServer.handleFTP();
}
```

> [!TIP]
> При подключении через программы с многопоточным интерфейсом (FileZilla, WinSCP) рекомендуется в настройках соединения ограничить максимальное количество одновременных подключений до **1**.
